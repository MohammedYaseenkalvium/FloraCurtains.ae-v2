# Flora Curtains — Design System

> For token values, docs/design-system.md wins.
## 1. Design Philosophy

Flora Curtains should feel like a premium interior-design studio.

Visual references should communicate:

- architecture
- luxury
- craftsmanship
- materiality
- calm
- warmth
- precision

The interface should feel designed, not generated.

# 3. Typography

Use a premium editorial hierarchy.

Large headings:
- elegant serif or display typeface where appropriate

Body:
- highly readable modern sans-serif

UI:
- clean sans-serif

Typography should create strong contrast between:

- editorial content
- operational UI
- metadata

---

# 4. Spacing

Use generous whitespace.

Preferred spacing scale:

4
8
12
16
24
32
48
64
80
96
120

Avoid cramped layouts.

---

# 5. Radius

Use rounded corners consistently.

Small:
8px

Medium:
12px

Large:
16px

Hero:
24px+

Do not make every element excessively rounded.

---

# 6. Shadows

Use subtle shadows only.

Avoid:

- heavy drop shadows
- glowing cards
- excessive depth

---

# 7. Glassmorphism

Glassmorphism is allowed for:

- navigation overlays
- floating controls
- hero cards
- selected overlays
- contextual panels

Use:

- translucent background
- backdrop blur
- subtle border
- restrained shadow

Do not make the entire application glass.

Homepage structure:

1. Navbar
2. Hero
3. Experience / company story

5. Featured work / portfolio

7. Why Flora

# 9. Hero

Hero should feel cinematic.

Use:

- large interior image
- dark overlay
- strong headline
- supporting copy
- primary CTA
- secondary CTA
- subtle animation

Example:

Transforming Spaces
with Style, Comfort
& Elegance

CTA:

Get a Quote

Secondary:

Explore Our Work

---

# 10. Services

Services should be visual.

Use:

- large imagery
- asymmetric layouts
- editorial cards
- short descriptions
- clear CTA

Do not use a generic six-card SaaS grid.

---

# 11. Portfolio

Portfolio should feel like an interior design publication.

Use:

- large images
- varied image ratios
- category labels
- subtle hover interactions
- minimal text

Do not fabricate project names or clients.

---

# 12. About

About should communicate:

Established:
2023

Experience:
Since 1997

Make this distinction visually obvious.

---

# 13. CRM Design

CRM follows the same brand language but is optimized for operations.

Structure:

App Shell
+
Persistent Navigation
+
Page Header
+
Contextual Content

Dashboard:

- overview
- KPI cards
- urgent items
- recent activity
- upcoming work

---

# 14. CRM Cards

CRM cards should be:

- clean
- compact
- informative
- readable

Each card should have a clear purpose.

---

# 15. Tables

Tables should be used for operational data.

Must support:

- sorting where useful
- filtering where useful
- search
- pagination where required
- row actions
- responsive behavior

---

# 16. Status System

Use consistent status badges.

Examples:

DRAFT
PENDING
APPROVED
IN_PROGRESS
COMPLETED
CANCELLED

Status colors must remain consistent throughout the CRM.

---

# 17. Buttons

Primary:
Burgundy background + light text

Secondary:
Light neutral background

Ghost:
Transparent

Danger:
Reserved for destructive operations

---

# 18. Forms

Forms should feel calm and structured.

Use:

- clear labels
- grouped sections
- helpful descriptions
- consistent inputs
- inline validation
- clear primary action

---

# 19. Responsive Design

Desktop:
Full experience

Tablet:
Condensed layouts

Mobile:
Single-column layouts
Persistent mobile navigation
Large touch targets

Never simply shrink desktop UI.

---

# 20. Motion

Motion should communicate:

- hierarchy
- state
- transition
- interaction

Use:

- fade
- slide
- scale
- stagger
- subtle parallax

Avoid:

- excessive bouncing
- unnecessary spinning
- constant movement

---

# 21. Image Rules

Images should feel:

- premium
- warm
- architectural
- realistic
- editorial

Avoid generic AI-looking stock imagery where real company imagery is available.

---

Related pages must look like the same product.

Examples:
